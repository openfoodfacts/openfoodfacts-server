**Implementation notes / decisions made during coding:**

- **Data file path**: the module loads
  `$data_root . "/external-data/ecobalyse/processes_packaging_matched.json"`
  (in the container `$data_root` resolves to `/mnt/podata`). The same file is also
  present at `/opt/product-opener/external-data/ecobalyse/` (bind-mounted).
- **Canonical tagids required**: `is_a()` only matches canonical taxonomy tags. The
  material/shape mapping tables therefore map Ecobalyse strings to the *canonical*
  OFF tagids (e.g. `'PP' => 'en:pp-5-polypropylene'`, `'flask' => 'en:vial'`,
  `'multi-material' => 'en:composite-material'`, `'foil' => 'en:aluminium-foil'`).
  `canonicalize_taxonomy_tag()` was used to determine them.
- **Category-less proxies must zero their `categories_tagid`**: without this they keep
  their original category and incorrectly get a category-specificity level. They are
  now stored as shallow copies with `categories_tagid = ''` so they score category
  specificity 0.
- **Scoring weights** (as designed): material 100/80, shape 70/56, category
  specificity = raw taxonomy level (0–10, via `get_taxonomy_tag_level`), quantity
  distance 0–5, ECS tiebreaker on equal totals.
- **Manual proxies** (`packaging_proxies.tsv`) are indexed per category and pushed as
  candidates alongside the exact-category matches; their category specificity comes
  from the *listed* category level (no special-casing needed).

## Goal

1. Read `external-data/ecobalyse/processes.json` and extract all items whose
   `categories` array contains the value `"packaging"` **and** whose `unit`
   field is `"item"` (the per-product-item materials).
2. Optionally filter the result to a given Ecobalyse **scope** via a
   `--scope` parameter: only items whose `scopes` array contains the given
   value (`food` or `food2`) are kept. When omitted, both scopes are included.
3. For each matching item, extract the fields `activityName`, `displayName`,
   `id`, `ecs` (nested under `impacts.ecs`), and `scopes`.
4. Write a second script that parses `activityName` / `displayName` to extract:
   - packaging shape (e.g. bag, bottle, tray, jar, box) and material (e.g. OPP,
     PP, aluminium, cardboard, glass)
   - the food category (the food/product family the packaging is for)
   - the quantity (weight in grams or volume in L / cl)
5. Match the extracted food category to the Open Food Facts categories taxonomy
   using the canonicalization functions in `lib/ProductOpener/Tags.pm`.

> **Status:** Both scripts are implemented (see §"Status" above). The
> canonicalization uses a multi-tier fallback: English full → English stripped of
> ` - cat X` descriptor → English last word → French full → French first comma
> segment → French with parentheticals stripped.

## `activityName` format

The 592 `unit == "item"` items follow this pattern:

```
<food category>[, <variant>], <quantity><unit> | Packaging System, <pack-type>, <shape/material description> {FR} U
```

Examples:
```
Asian pasta, 250g | Packaging System, N0, All, OPP bag {FR} U
Baby food, Powder, 800g | Packaging System, Proxy Pack, Steel {FR} U
Beef and veal, 244g | Packaging System, N0, All, Tray in a metallic plastic bag {FR} U
Olive oil, 0,75L | Packaging System, N0, All, Glass bottle {FR} U
Still wine, 5L | Packaging System, N0, All, Wine box 5L with recyclable pocket {FR} U
```

The food category lives in the substring **before** ` | Packaging System`. The
quantity is a trailing token (`250g`, `0,75L`, `5L`, `25cl`, ...). European
decimal comma is used for volume quantities (e.g. `0,75L`).

### Material-only / per-kg entries (24 items, excluded)

The 24 `unit == "kg"` entries have activity names without a food/quantity
prefix:

```
Aluminium packaging
Cardboard packaging
Glass packaging
PEHD packaging
PELD packaging
PET packaging
PP packaging
PS packaging
PVC packaging
Paper packaging
Steel packaging
Wood packaging
```

These are generic per-kg material datasets (each material appears twice, likely
once per source). They are **excluded** from this analysis: we only process the
**per-item** (`unit == "item"`) packaging entries.

### `displayName` (French) format

```
<Material shape> (<code>) pour <food category> - <quantity>[- <proxy>]
```

Examples:
```
Sachet en plastique (OPP) pour pâtes asiatiques - 250g
Pot en plastique (PP) pour dessert pour bébés - 250g - Proxy
Bouteille en verre pour bière - 1500g - Proxy
Feuille en aluminium pour beurre - 250g
Barquette en plastique (APET/PE) pour viandes (hors volaille) - 250g
```

The French food category follows `pour` and is often richer than the English one
in `activityName` (e.g. `pour viandes (hors volaille)` vs `Beef and veal`).
`displayName` will be used as a fallback / enrichment when the English
`activityName` food category fails to match the taxonomy.

## Reference: taxonomy + canonicalization (`lib/ProductOpener/Tags.pm`)

- Taxonomy file: `taxonomies/food/categories.txt` (~128 724 lines).
- Taxonomies are loaded automatically at module compile time via
  `init_taxonomies(0)` which calls `retrieve_tags_taxonomy()` for every
  entry in `@ProductOpener::Config::taxonomy_fields`
  (`lib/ProductOpener/Tags.pm:2751`, `2782`-`2784`, `5191`).
- The canonicalization entry point is:

```perl
canonicalize_taxonomy_tag($tag_lc, $tagtype, $tag, $exists_in_taxonomy_ref = undef)
```

- `$tagtype` for categories is `"categories"` (see `%taxonomy_fields` mapping).
- `$tag_lc` is a language code: `"fr"` for French strings, `"en"` for English,
  `"xx"` for language-less.
- Returns the canonical tag id (e.g. `en:biscuits`) if matched, otherwise
  `en:<string-id>` with `$exists_in_taxonomy_ref` set to `0`.
- It already applies: linked-data / weblink resolution, synonym lookup,
  stopword removal (`stopwords:fr: aux, au, de, le, du, la, a, et, avec, base`),
  and plural removal.
- Calling convention from existing code
  (`lib/ProductOpener/ImportConvert.pm:206`):
  ```perl
  my $canon_tagid = canonicalize_taxonomy_tag($product_ref->{lc}, $field, $value);
  ```
- `lib/ProductOpener::Store::get_string_id_for_lang($lc, $string)` normalizes a
  raw string into a tag id (`"en:Yule Log"` -> `"en:yule-log"`); useful for
  fallback ids and for building the plain name.

## Script 2: parse fields + match to the categories taxonomy

**Path:** `scripts/match_ecobalyse_packaging_categories.pl`

Depends on `lib/ProductOpener/Tags.pm` (so it can call
`canonicalize_taxonomy_tag`). Because Tags.pm auto-loads taxonomies at
compile (`lib/ProductOpener/Tags.pm:5191`), the script should set
`PO_NO_LOAD_DATA` only if a quick syntax check is needed; otherwise just
`use ProductOpener::Tags`.

Read its input from the file produced by Script 1
(`external-data/ecobalyse/processes_packaging.json` by default, or
`processes_packaging_<scope>.json` when Script 1 was run with `--scope`).
Accept an `--input` option to override the input path.

### 2a. Extracting packaging shape & material

**Shape**: use the **first** `packaging_type:*` tag from `categories`. Strip the
`packaging_type:` prefix to get e.g. `bag`, `bottle`, `tray` (10 shapes total).

**Material**: mined from the `activityName` pack description (the text between
`Packaging System, <pack-type>,` and `{FR}`), case-insensitively for the common
materials: `OPP`, `APET`, `PE`, `PP`, `PET`, `PS`/`EPS`/`PSE`, `HDPE`/`PEHD`,
`LDPE`/`PELD`, `EVOH`, `alu(minium)`, `glass`/`verre`, `cardboard`/`carton`,
`paper`, `steel`, `wood`, `kraft`, `plastic`, `foil`.

When the pack description yields no material (e.g. "Sold by weight",
"Wine box", "Bricks pack"), fall back to `extract_material_from_display_name()`
which checks the **`displayName`'s** parenthetical code first — e.g.
`(APET)` → `APET`, `(PP)` → `PP`, `(multimatériaux)` → `multi-material` — then
keyword-matches the full `displayName`. This covers multi-material / bag-in-box
entries and brings the "undef" material count to zero.

### 2b. Extracting food category + quantity from `activityName`

All `unit == "item"` entries match `/^(.*?)\s*\|\s*Packaging System,/`. Capture
the prefix `$foodpart` (everything before `| Packaging System`). Then:

- **quantity**: match the trailing `<number><unit>` token with
  `qr/^(.*?),\s*(\d+(?:[.,]\d+)?)\s*(cl|g|L)\s*$/i`. Uses an explicit capture
  group (`$1` for food category) instead of `$`` to avoid Perl's global
  match-variable side effects. Convert European decimal comma to dot and force
  numeric.
- **food category**: `$1` from the above regex (everything before the last
  `, <quantity><unit>`). Then strip an optional variant segment (the part after
  the first comma in the food name). E.g.:
  - `"Asian pasta, 250g"` -> category `Asian pasta`
  - `"Baby food, Powder, 800g"` -> category `Baby food`, variant `Powder`
  - `"Beef and veal, 244g"` -> category `Beef and veal`
  - `"Olive oil, 0,75L"` -> category `Olive oil`, quantity `0.75` `l`
  - `"Ice cream cup, 266,4g"` -> category `Ice cream cup`, quantity `266.4` `g`

### 2c. Extracting food category from `displayName` (French fallback)

When the English food category (2b) does **not** match the taxonomy, try the
French category extracted from `displayName`:

- Match `pour\s+(.+)` and capture `$1` (everything after "pour"). Handles cases
  where the food name itself contains "pour" (e.g. "dessert pour bébés").
- Remove trailing ` - Proxy` / ` - Sans marque`.
- Strip trailing quantity: single (` - 250g`) and range (` - 0,5L à 1L`,
  ` - 250g à 350g`) formats.
- If the `displayName` has no `pour` (some glass jar / bottle entries), the
  French food category is left empty — English fallbacks in 2d will still apply.

### 2d. Matching to the taxonomy

Multi-tier fallback (in order):

1. **English full** food category (e.g. `"Biscuits"` → `en:biscuits`)
2. **English stripped** of ` - cat X` / descriptor suffix (e.g. `"Blue cheeses - cat A"` → `"Blue cheeses"` → `en:blue-veined-cheeses`)
3. **English last word** (e.g. `"Still wine"` → `"wine"` → `en:wines`; `"Asian pasta"` → `"pasta"` → `en:pastas`)
4. **French full** food category
5. **French first comma segment** (e.g. `"anchois, ambiant"` → `"anchois"`)
6. **French with parentheticals stripped**

```perl
my $tagid = canonicalize_taxonomy_tag("en", "categories", $en, \$exists);
# then progressively simpler fallbacks (see above)
$tagid = canonicalize_taxonomy_tag("fr", "categories", $fr, \$exists);
```

Record per item:

  "activityName": "...",
  "displayName": "...",
  "ecs": 3.942,

## Research: Matching OFF products to Ecobalyse packaging entries

### OFF product packaging data model

OFF products already carry structured packaging data (populated by
`ProductOpener::Packaging`, see `lib/ProductOpener/Packaging.pm`):

- **`categories_tags`** — e.g. `["en:pastas", "en:breakfast-cereals"]`
- **`product_quantity` / `product_quantity_unit`** — product net weight (e.g.
  `250`, `"g"`) or volume
- **`packaging_materials_tags`** — e.g. `["en:glass", "en:steel"]`; extracted from
  `packaging` text via the `packaging_materials` taxonomy regexes
  (`Packaging.pm:178`, `Packaging.pm:199-201`).
- **`packaging_shapes_tags`** — e.g. `["en:bottle", "en:jar"]`
- **`packagings`** — structured array of components, each with `material`,
  `shape`, `quantity_per_unit`, `weight_measured` fields.

The `foodture/representative_products.csv` confirms this model with columns
`packaging_N_shape`, `packaging_N_material`, `packaging_N_quantity_per_unit`.

| `en:Plastic` (parent) | `plastic` |
| `en:composite material, Multilayer composite` | `multi-layer plastic` / `multi-material` |

### Scope equivalence

`food` and `food2` scopes have **identical ECS values** for matching
category+material combinations (verified across all 592 entries). The two scopes
are effectively duplicate datasets. The matching script can therefore merge both
scopes or use either one interchangeably.

### Scoring-based matching strategy

Rather than a tiered fallback, every candidate Ecobalyse entry is **scored** and
the highest-scoring entry wins. This avoids getting stuck with a mismatched
material just because the category was a closer fit.

#### Candidate generation

For a product with `categories_tags`, `packaging_materials_tags`,
`packaging_shapes_tags`, `packagings` (structured array), and
`product_quantity`:

1. **All product categories**: pre-build a hash `%by_category { category_tagid => [ @entries ] }`
   from the matched Ecobalyse data. Since a product's `categories_tags` already
   includes ALL ancestor categories (e.g. `["en:breakfast-cereals", "en:cereals",
   "en:plant-based-foods", ...]`), an exact hash lookup is sufficient — no
   `is_a()` traversal is needed for candidate *generation*. Iterate the
   product's `categories_tags` and look up `@entries` in `%by_category`.

2. **Category-less proxy entries** (see §"Proxy entries strategy" below):
   entries with no food category that match by material + shape only.

3. **Per-kg material entries** (the 24 `unit == "kg"` entries): **OUT OF SCOPE.**
   Excluded entirely. With category-less proxies we always match something.

#### Scoring factors (weighted)

| Factor | Weight | How it's computed |
|--------|--------|-------------------|
| **Material match** | 100 | Exact match = 100; parent/child via `is_a()` (either direction) = 80; no match = 0 |
| **Shape match** | 70 | Same logic as material (both directions: OFF→Ecobalyse or Ecobalyse→OFF); exact = 70, `is_a()` = 56 |
| **ECS tiebreaker** | +0.01 | If two entries have equal total scores, the one with higher `ecs` wins (favors heavier packaging like glass over light plastic) |
| **Category specificity** | 0–10 | `get_taxonomy_tag_level("categories", tagid)` — raw taxonomy depth (higher = more specific). Category-less = 0 |
| **Quantity distance** | 0–5 | `5 * (1 - |qty_diff| / qty)`, capped at 0; only counted if material+shape both match (>0) |

> **Weight changes from initial plan:** category specificity weight reduced
> from 30 → 10 (using raw taxonomy level 0–10), quantity from 15 → 5, to keep
> them as minor tiebreakers behind the dominant material (100) + shape (70)
> factors.

#### Research: category levels scale

Examined `%level{categories}` (populated in `Tags.pm` during taxonomy build,
`lib/ProductOpener/Tags.pm:2029`-`2062`). The hash maps each canonical category
tagid to its depth in the taxonomy tree (1 = root, 10 = deepest).

Distribution (14 628 total entries with levels):

| Level | # tags | Typical categories |
|-------|--------|---------------------|
| 1     | 12 522 | Root entries (e.g. broad top-level) |
| 2     | 1 283 | `en:mayonnaises` |
| 3     | 458   | |
| 4     | 181   | `en:olive-oils`, `en:sauces` |
| 5     | 95    | `en:biscuits`, `en:sardines`, `en:beef` |
| 6     | 48    | `en:meats` |
| 7     | 24    | `en:wines` |
| 8     | 10    | |
| 9     | 5     | `en:plant-based-foods` |
| 10    | 2     | |

**Decision:** use the raw level value (0–10) as the category specificity score,
where 0 = category-less (no level). No normalization needed — this keeps the
factor naturally minor compared to material (100) and shape (70).

`get_taxonomy_tag_level($tagtype, $tagid)` returns `$level{$tagtype}{$tagid} // 0`.

#### Material/shape matching with `is_a()` (both directions)

```perl
# Returns match quality: 100 (exact), 80 (is_a either direction), 0 (no match)
sub material_score {
    my ($off_tag, $ecobalyse_material) = @_;
    return 100 if $off_tag eq $ecobalyse_material_canonical;
    # ecobalyse_material is e.g. "glass"; OFF tag is e.g. "en:green-glass"
    return 80 if is_a("packaging_materials", $off_tag, $ecobalyse_material_tag);
    # Ecobalyse is more specific: e.g. ecobalyse has "PP" but OFF has "plastic"
    return 80 if is_a("packaging_materials", $ecobalyse_material_tag, $off_tag);
    return 0;
}
```

- `is_a("packaging_materials", $off_tag, $ecobalyse_tag)` — OFF is more specific
  (e.g. `en:green-glass` is_a `en:Glass` → matches `"glass"`)
- `is_a("packaging_materials", $ecobalyse_tag, $off_tag)` — Ecobalyse is more
  specific (e.g. `"PP"` → `en:PP 5` is_a `en:Plastic` → matches `"plastic"`)
- Also map Ecobalyse material strings to OFF taxonomy tags (see mapping table)

#### Shape + material in same packaging component

OFF products have a `packagings` array where each component has `material`,
`shape`, and (optionally) `quantity_per_unit`. For each component, check if its
shape+material matches an Ecobalyse entry. This is more precise than checking
`packaging_materials_tags` and `packaging_shapes_tags` independently (which are
flat merged lists across all components).

```perl
for my $pkg (@{$product->{packagings}}) {
    for my $entry (@candidate_entries) {
        $score = material_score($pkg->{material}, $entry->{packaging_material})
                + shape_score($pkg->{shape}, $entry->{packaging_shape});
        # Only material+shape matches in same component get full weight
    }
}
```

#### Proxy entries strategy

To handle cases like "sardines in glass jar" when Ecobalyse only has "sardines
in metal box", we add **proxy entries**: Ecobalyse entries that can apply to
product categories they were not originally tagged for. Proxy specificity uses
the same level-based category specificity — no special handling.

**Strategy — two phases:**

1. **Automatic generic proxies** (Phase 1 — at data load time):
   - Create **category-less** proxy entries — 1 for each unique combination of
     `(packaging_shape, packaging_material, quantity rounded to nearest 100g)`.
   - For each combination, select the Ecobalyse entry with the closest quantity
     to the rounded value. If ties, take the first one sorted by `activityName`.
   - These proxies have `categories_tagid = ""` (category-less) → category
     specificity = 0. They are always available as candidates and ensure we
     always get a match.

2. **Manual proxy configuration** (Phase 1 + Phase 2):
   - A TSV file: `external-data/ecobalyse/packaging_proxies.tsv`
   - Columns: `ecobalyse_id`, `name_en`, `name_fr`, `categories` (comma-separated
     OFF category tags the entry should also apply to)
   - Each row means: "this Ecobalyse entry ID also applies to these categories"
   - The category specificity is computed from the **matched** category's level
     (using `get_taxonomy_tag_level`). If the product belongs to multiple listed
     categories, use the most specific (highest level) one.
   - Phase 1: empty/minimal file. Phase 2: manually curated mappings.

**`get_taxonomy_tag_level($tagtype, $tagid)`** — a new helper in `Tags.pm`:
wraps the existing `%level{$tagtype}{$tagid}` hash to return the depth of a
taxonomy tag (higher number = more specific). Returns 0 if undefined.

#### Per-kg material fallback — OUT OF SCOPE

The 24 `unit == "kg"` per-kg material entries (generic material datasets like
`Aluminium packaging`, `Glass packaging`) are **out of scope for now**. With
category-less proxy entries (see §"Proxy entries strategy"), we always match
something — the per-kg fallback is not needed in the initial implementation.

#### Implementation sketch

```perl
# Pre-built indexes (at startup, cached):
%by_category          { category_tagid => [ @entries ] }         # exact hash lookup
%proxies_categoryless  { "mat|shape|qty_rounded" => entry }      # 1 per unique mat+shape+100g
%proxies_manual        { category_tagid => [ @entries ] }       # from packaging_proxies.tsv

sub find_best_ecobalyse_entry($product_ref) {
    my @candidates;
    my $best_score = -1;
    my $best_entry;
    my $best_ecs = -1;

    # 1. Collect candidates from all product categories (exact hash lookup)
    for my $cat_tag (@{$product_ref->{categories_tags}}) {
        push @candidates, @{$by_category{$cat_tag} // []};
    }
    # Add category-less proxies and manual proxies
    push @candidates, values %proxies_categoryless;
    for my $cat_tag (@{$product_ref->{categories_tags}}) {
        push @candidates, @{$proxies_manual{$cat_tag} // []};
    }

    # 2. Score each candidate
    for my $entry (@candidates) {
        my $material_score = 0;
        my $shape_score = 0;

        # Match against each packaging component (shape+material in same component)
        for my $pkg (@{$product_ref->{packagings} // []}) {
            $material_score = max($material_score,
                material_score($pkg->{material}, $entry->{packaging_material}));
            $shape_score = max($shape_score,
                shape_score($pkg->{shape}, $entry->{packaging_shape}));
        }

        # Category specificity: raw taxonomy level (0 for category-less)
        my $cat_level = ($entry->{categories_tagid})
            ? get_taxonomy_tag_level("categories", $entry->{categories_tagid})
            : 0;

        # Quantity distance (only if material+shape both match at all)
        my $qty_score = 0;
        if ($material_score > 0 && $shape_score > 0) {
            my $diff = abs(($entry->{quantity} // 0) - ($product_ref->{product_quantity} // 0));
            $qty_score = 5 * max(0, 1 - $diff / max(1, $entry->{quantity} // 1));
        }

        my $total = $material_score + $shape_score + $cat_level + $qty_score;

        # ECS tiebreaker: on equal scores, prefer higher-impact entry
        if ($total > $best_score || ($total == $best_score && $entry->{ecs} > $best_ecs)) {
            $best_score = $total;
            $best_ecs = $entry->{ecs};
            $best_entry = $entry;
        }
    }

    return $best_entry;  # may be undef if no candidates at all (should not happen)
}
```

### Performance considerations

- The 592-entry JSON (~380 KB pretty-printed, ~300 KB compact) is loaded once at
   startup and indexed into Perl hashes → all lookups are **O(1)** average.
- Each product's `packagings` array typically has 1–5 components; scoring is
  O(candidates × components), where candidates per category is small (average
  ~2 per category, max ~10).
- `is_a()` uses the pre-built taxonomy parent/child tables (also O(1) lookups).
- `food`/`food2` scopes are deduplicated (identical data, verified across all 592
  entries).
- No API calls needed (all data is local in `processes_packaging_matched.json`).
- Total per-product lookup: **well under 1 ms**, suitable for real-time scoring
  and batch processing of millions of products.
- Category-less proxies add a constant ~100–200 additional candidates (one per
  unique mat+shape+100g bucket); these are pre-indexed so lookups remain O(1).

#### Manual proxy configuration file

Phase 2: a TSV file (`external-data/ecobalyse/packaging_proxies.tsv`) that maps
a specific Ecobalyse entry to additional OFF categories it should also apply to.

| Column | Description |
|--------|-------------|
| `ecobalyse_id` | UUID of the Ecobalyse entry |
| `name_en` | English `activityName` (for reference) |
| `name_fr` | French `displayName` (for reference) |
| `categories` | Comma-separated OFF category tags (e.g. `en:sauces,en:mayonnaises`) |

Each row means: "this Ecobalyse entry also applies to these categories." The
category specificity is computed from the **matched** category's level via
`get_taxonomy_tag_level("categories", $cat_tag)`. If a product matches multiple
listed categories, use the most specific (highest level) one. This means proxies
need no special handling — they use the same level-based specificity as regular
entries.
